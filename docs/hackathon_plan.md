# План хакатона ШЦТ: Telegram-бот или Qt-приложение на готовом API

Один день, 10:00–17:00. Команды по 2–3 человека, 11–17 лет. Каждая команда за день делает работающий Telegram-бот или Qt-приложение на данных из API хакатона и показывает его на демо.

Допущения, которые стоит подтвердить: день один (а не два), до 30 участников, на каждую команду есть хотя бы один компьютер с Python 3.10+.

## Треки

Команда выбирает один трек в начале дня. Оба трека используют одни и те же данные и одинаково оцениваются.

| | Telegram-бот | Qt-приложение |
| --- | --- | --- |
| Библиотека | pyTelegramBotAPI (`telebot`) | PyQt6 |
| Шаблон | `examples/bot_example.py` | `examples/qt_example.py` |
| Что получится | Бот, которому можно написать с телефона | Окно с кнопками, списками и картинками |
| Чему учит | Обработчики команд, кнопки в чате, состояние диалога | Виджеты, сигналы и слоты, раскладки |
| Плюс | Легко показать на демо и друзьям | Не нужен Telegram и токен, всё работает офлайн с сервером в классе |
| Подводный камень | Нужен токен от @BotFather и доступ к Telegram из сети школы | Картинки Wikimedia грузятся только с заголовком `User-Agent` |
| Кому подходит | Тем, кто хочет быстрый результат | Тем, кто любит рисовать интерфейсы |

## Расписание дня

| Время | Что происходит | Результат к концу блока |
| --- | --- | --- |
| 10:00–10:20 | Открытие: презентация, правила, адрес сервера на доске | Все знают задачу и критерии |
| 10:20–10:40 | Разминка: открыть `/docs`, сделать первый запрос из Python | У каждого в консоли напечатан случайный фильм |
| 10:40–11:00 | Команды, выбор трека и идеи | Идея записана одной фразой у ментора |
| 11:00–13:00 | Работа: минимальная версия | **Чекпоинт в 12:00:** бот или окно показывает данные из API |
| 13:00–13:40 | Обед | — |
| 13:40–15:30 | Работа: уровни 3–6 (см. ниже) | **Чекпоинт в 14:30:** есть кнопки или фильтр |
| 15:30–15:45 | Код заморожен, подготовка демо | Программа запущена и готова к показу |
| 15:45–16:45 | Демо: 3 минуты на команду + 1 минута вопросов | Все команды выступили |
| 16:45–17:00 | Подведение итогов, награждение | Победители и номинации |

Чекпоинты нужны, чтобы вовремя заметить застрявшие команды. Если к 12:00 команда не получила данные, ментор садится с ней и доводит первый запрос до конца.

## Уровни прокачки

Команда проходит уровни по порядку. Уровень засчитывается, только когда он работает на демо.

1. **Данные.** Программа получает запись из API и показывает её текстом.
2. **Картинка.** Рядом с текстом показывается фото из `img_url`.
3. **Управление.** Кнопки или меню: в боте — `InlineKeyboardMarkup`, в Qt — `QPushButton`, `QComboBox`.
4. **Ввод пользователя.** Фильтр или поиск по тому, что ввёл пользователь: жанр, страна, имя автора.
5. **Надёжность.** Программа не падает на 404, пустой картинке и неверном вводе.
6. **Своя фишка.** То, чего нет в API: очки в викторине, избранное, история, таймер, статистика.

## Критерии оценки

Жюри — преподаватели и менторы. Каждый ставит баллы по таблице, баллы суммируются.

| Критерий | Баллы | На что смотрим |
| --- | --- | --- |
| Работает | 30 | Программа запускается и не падает на демо |
| Использование API | 20 | Сколько эндпоинтов и есть ли фильтры, поиск, параметры |
| Удобство | 20 | Понятно ли без объяснений, как пользоваться |
| Идея и своя фишка | 15 | Есть ли то, чего нет в API (уровень 6) |
| Презентация | 15 | За 3 минуты понятно, что сделано и зачем |

Номинации помимо мест: «Самый полезный», «Самый смешной», «Лучший интерфейс», «Лучший первый проект» — для команды, где все пишут код впервые.

## Подготовка

**За неделю:**

- [ ] Решить, где работает сервер API (ноутбук преподавателя или сервер в классе), и проверить `/ping` с ученического компьютера.
- [ ] Проверить, что из сети школы открывается Telegram. Если нет — оставить только Qt-трек или раздать мобильный интернет.
- [ ] Заменить или удалить факт №1 «BMW в Египте» (см. конспект, раздел 6).
- [ ] Отправить с тестовым ботом фото из нескольких `img_url`: убедиться, что Telegram скачивает картинки с Wikimedia.

**Накануне:**

- [ ] Поставить на компьютеры детей Python и `pip install -r examples/requirements.txt`.
- [ ] Скачать Docker-образ `python:3.14-slim`, если сервер будет в Docker.
- [ ] Распечатать или вывести на экран адрес сервера и ссылку на `/docs`.
- [ ] Пересобрать презентацию с адресом сервера: `python3 presentation/build_slides.py --server <IP>`. Без `--server` на последнем слайде остаётся пропуск.
- [ ] Каждой команде бот-трека — создать бота в @BotFather или показать, как это сделать за 2 минуты.

**Утром:**

- [ ] Запустить сервер, открыть `/ping` и `/docs` с двух разных ученических компьютеров.
- [ ] Написать на доске адрес сервера крупно.

## Роли

| Роль | Сколько | Что делает |
| --- | --- | --- |
| Ведущий | 1 | Открытие, тайминг, чекпоинты, демо |
| Ментор | 1 на 3–4 команды | Помогает командам; первым делом — тем, кто застрял на чекпоинте |

## Если что-то пошло не так

| Проблема | План Б |
| --- | --- |
| Сервер упал или ноутбук выключился | `make run` на втором ноутбуке; новый адрес на доску |
| Telegram недоступен в сети школы | Перевести команды на Qt-трек или раздать мобильный интернет |
| Картинки не грузятся у всего класса (429) | Показывать картинку только по кнопке, не качать в цикле |
| Команда не успевает | Сократить цель до уровня 2 — работающий показ данных с картинкой тоже засчитывается |
